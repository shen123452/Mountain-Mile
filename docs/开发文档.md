## 1. 参考项目的 Agent 体系全景

精读 summer-checkin 后，其 agent 体系由 **5 层**构成，这是我们要完整移植的部分：

```
┌─────────────────────────────────────────────────────────┐
│ ⑤ 调度层  AgentSchedule（用户级 cron）+ 每日 cron 路由     │
│    每日自动运行 / 周日周报 / 通知清理 / 冷记忆淘汰          │
├─────────────────────────────────────────────────────────┤
│ ④ 交互层  对话（Conversation/Message，流式）              │
│    AgentWorkspace（运行列表 + 审批 UI）+ 通知中心          │
├─────────────────────────────────────────────────────────┤
│ ③ 执行层  14 个 function-calling 工具（AI SDK tool()）    │
│    计划 5 · 任务 4 · 待办 4 · RAG 1                       │
├─────────────────────────────────────────────────────────┤
│ ② 运行时  Observe → Analyze+Plan → Execute 状态机         │
│    LLM JSON 结构化分析 + 规则兜底；5 种 Action            │
├─────────────────────────────────────────────────────────┤
│ ① 持久化  AgentRun / AgentStep / AgentApproval            │
│    AgentDecision / AgentToolCall / UserMemory            │
└─────────────────────────────────────────────────────────┘
```

**运行时四步（`app/agent/orchestrator.py`）**：

1. **Observe**：并行收集打卡、活跃计划（含任务统计）、待办、目标类记忆、今日专注；
2. **Analyze + Plan**：LLM 以 `response_format=json_object` 输出 `{ status, summary, findings[], actions[] }`，失败时走阈值规则兜底（`fallbackAnalysis`）；
3. **Approve**：findings 与 actions 生成 AgentApproval，关键写入等待用户确认；
4. **Execute**：按 5 种 action 类型执行——`ADJUST_PLAN / CREATE_TASK / SEND_REMINDER / GENERATE_REPORT / ENCOURAGE`，结果写回并记录 AgentDecision。

**计划生成服务（`app/services/plans.py`）**：目标 → 生成草案（模型失败回落内置 7 天草案）→ `awaiting_approval` → 用户批准后事务性写入 `plans` + `plan_tasks` + Markdown 文档；支持拒绝（带理由）、取消、列表、序列化。

**报告（`app/reports/daily.py` / `app/reports/weekly.py`）**：日报（强弱项 + 建议）、周报（纯统计不耗 LLM，按周去重落库为通知）。

**必须认识到的一点**：原版 agent 能力虽全，但**过程不是实时流式的**（要刷新看结果）、**单角色**（一个 coach prompt 包打天下）、**自主程度不可配**、**没有可观测面板**、**复习排期缺失**——这正是我们的差异化空间。

## 2. 新项目定位：Agent 优先

### 2.1 一句话介绍

**「山程」是一个 agent 优先的 3D 学习成长应用：你拥有一支五人学习智能体小队，他们观察你的学习数据、调用工具规划与执行、在关键决策前请你确认；而每个学习目标，都是一座随这些动作真实生长的青绿体素山屿。**

### 2.2 产品 = Agent 团队 + 学习数据 + 地形可视化

| 组成 | 角色 |
|---|---|
| Agent 团队 | 产品的"发动机"：规划、执行、复盘、记忆、巡逻，全部动作经工具调用落地 |
| 学习数据层 | 目标 / 任务 / 待办 / 专注 / 打卡 / 知识库 / 记忆（PostgreSQL） |
| 3D 群岛 | Agent 状态的"仪表盘"：岛屿升降、地块解锁、记忆树、灯塔、旗帜 |

### 2.3 用户的一天（核心仪式）

```
晨间  向导主动汇报：昨日完成情况 + 今日任务清单（getTodayTasks）
       └ 你确认/调整 → 今日计划落定
白天  进入山屿 → 番茄专注 25 分钟（沉浸遮罩）
       └ 完成：Executor 记录专注、更新任务、解锁地块（流式可见）
       └ 若 agent 想改计划/加任务 → 弹出审批，你可批准/拒绝/改参数
晚间  Reflector 引导 30 秒反思：完成度、偏差、心情
       └ Curator 提取记忆，Scout 排定明日与到期复习
周日  自动周报 + 下周建议 + 复习清单
随时  对话："帮我做一个 30 天英语口语计划""第三章讲了什么""我最近状态怎么样"
```

### 2.4 与参考项目的差异对照

| 维度 | summer-checkin | 山程 |
|---|---|---|
| 产品定位 | 学习平台（含 agent 模块） | **agent 优先**，agent 是主体 |
| Agent 角色 | 单角色 coach | **五角色协作 + 委派** |
| 过程呈现 | 持久化、刷新查看 | **SSE 实时流式时间线，可中断** |
| 自主性 | 固定（关键步骤确认） | **三档自主程度 + 工具风险分级** |
| 可观测性 | TokenUsage 表 | **观测台：成本/成功率/耗时/轨迹回放** |
| 学习科学 | 无 | **SM-2 间隔复习 + 专注节律 + 达成预测** |
| 养成结构 | 全用户一座岛 | 一目标一山屿（群岛） |
| 视觉母题 | 雨林/雪/暖云 | 青绿山水（《千里江山图》） |
| 技术形态 | Next.js 单体 | Vue SPA + **Python FastAPI** 前后端分离 |

## 3. 技术选型：Vue + Python

### 3.1 为什么后端改 Python 完全可行、甚至更合适

1. **agent 的核心是 LLM function calling，与语言无关**：原版底层用的就是 OpenAI 兼容接口（`chat.completions.create` + tools），Python 的 `openai` SDK 一等公民支持，能力完全对等；
2. **Python 是 AI/agent 领域第一语言**：生态、面试官认知、资料丰富度都占优；
3. **文档解析 Python 更强**：PDF（pypdf）、DOCX（python-docx）比 Node 方案成熟；
4. **FastAPI 天然适合本项目**：全异步、Pydantic 数据校验、自动生成 Swagger 文档（`/docs`，演示加分）、SSE/WebSocket 支持好；
5. **前端零影响**：地形数学、小岛组件是纯前端 TS，后端语言与它无关。

### 3.2 技术映射表（TS 版 → Python 版）

| 职责 | 原计划（Node） | 现采用（Python） |
|---|---|---|
| Web 框架 | Express | **FastAPI** + Uvicorn(ASGI) |
| LLM 调用 | Vercel AI SDK | **openai（AsyncOpenAI）** |
| 数据校验 | zod | **Pydantic v2**（同时生成工具 JSON Schema） |
| ORM | Prisma | **SQLAlchemy 2.0（async，Mapped 注解）** |
| 数据库迁移 | prisma migrate | **Alembic**（autogenerate） |
| PG 驱动 | pg | **asyncpg** |
| 向量 | pgvector(prisma Unsupported) | **pgvector-python**（`Vector` 列 + 距离算子） |
| 密码/令牌 | bcrypt + jsonwebtoken | **bcrypt + PyJWT** |
| 定时任务 | node-cron | **APScheduler（AsyncIO）** |
| 文件上传 | multer | **FastAPI UploadFile** |
| SSE | 手写 chunked | **sse-starlette（EventSourceResponse）** |
| 测试 | Vitest + supertest | **pytest + pytest-asyncio + httpx** |
| 包管理 | pnpm | **uv**（前端仍用 pnpm） |

**③ 配置文件**：`backend/.env`（真实值，已被 .gitignore 排除）与 `backend/.env.example`（模板，提交）已创建；配置项通过 `pydantic-settings` 的 BaseSettings 读取。

## 4. Agent 总体架构

### 4.1 架构图

```
┌──────────────────────────────────────────────────────────┐
│ Vue 3 SPA                                                 │
│  AgentChat（对话+工具卡片）· RunTimeline（流式时间线）      │
│  ApprovalCard（审批）· Observatory（观测台）               │
│  VoxelIsland / ArchipelagoWorld（Three.js，动态加载）      │
└───────────┬──────────────────────────────────────────────┘
            │ REST + SSE（httpOnly Cookie 鉴权）
┌───────────▼──────────────────────────────────────────────┐
│ FastAPI (Uvicorn, async)                                  │
│  ┌─────────────┐  ┌──────────────┐  ┌──────────────────┐  │
│  │ Orchestrator│→ │ Agent Roles  │→ │ Tool Registry    │  │
│  │ (状态机/档位)│  │ (5 个角色)    │  │ (19 个工具/权限) │  │
│  └─────────────┘  └──────────────┘  └────────┬─────────┘  │
│  Memory Service · RAG Service · Report Service            │
│  APScheduler (AsyncIO)                                    │
└───────────┬──────────────────────────────┬───────────────┘
            │ SQLAlchemy(asyncpg)          │ AsyncOpenAI
┌───────────▼──────────────┐                 │
│ PostgreSQL 16 + pgvector │◄────────────────┘
└──────────────────────────┘
```

### 4.2 关键工程决策

1. **自研轻量编排器（Orchestrator）**：负责运行状态机、角色调度、审批暂停/恢复、中断（asyncio 取消）、步数上限与超时熔断；不引入 LangChain/LangGraph，原理自己掌握、面试能讲清；
2. **暂停-恢复模型**：审批点把运行上下文（消息历史、待执行工具调用、已用步数）序列化到 AgentRun.state，用户决策后从断点继续，而非重跑；
3. **流式用 SSE**：agent 过程与对话都是服务器→客户端单向流，SSE 比 WebSocket 简单且浏览器 EventSource 自带重连；不做多人聊天室故无需 WebSocket；
4. **全异步链路**：FastAPI + async SQLAlchemy + asyncpg + AsyncOpenAI，与 Node 版并发模型对等；
5. **两套 LOD 3D**：群岛页合并几何体，详情页完整体素（见第 14 节）。

### 4.3 运行状态机

```
queued ──► running ──┬──► awaiting_approval ──(approve)──► running
                     │                        └(reject)──► rejected
                     ├──► completed
                     ├──► failed（可重试，从最近检查点）
                     └──► cancelled（用户中断）
```

熔断规则：单 run 最大步数（默认 12）、单工具超时（默认 30s，asyncio.wait_for）、LLM 连续失败 2 次 → failed；规则兜底只用于"分析"，不用于写操作。

## 5. 多角色 Agent 设计（差异化）

### 5.1 五个角色

| 角色 | 职责 | 可用工具（白名单） | 触发时机 |
|---|---|---|---|
| **Planner 规划者** | 学情分析、制定/调整计划、拆分任务、排期 | createPlan, breakdownPlanTasks, getStudyStats, getPlanTasks, forecastGoal, detectOverload | 用户请求计划、晨间 |
| **Executor 执行者** | 记录专注、更新任务/待办状态、执行已批准动作 | updateTaskStatus, todo CRUD, getTodayTasks | 专注完成、用户指令 |
| **Reflector 复盘者** | 晚间反思、偏差分析、日报/周报、质量审查 | getRecentCheckins, analyzeFocusRhythm, 报告生成 | 晚间、周日 |
| **Curator 记忆官** | 记忆提取/去重/合并/淘汰、知识整理 | curateMemory, getMyMemories, 知识检索 | 每轮结束、晚间 |
| **Scout 向导** | 主动巡逻、提醒、间隔复习排期、目标闲置检测 | scheduleReview, getTodayTasks, SEND_REMINDER | 定时、晨间 |

### 5.2 协作机制

- **Orchestrator 持有主控**：每轮先判断该交给哪个角色（LLM 轻量路由 + 规则兜底）；
- **角色委派（handoff）**：角色可通过 `delegateToRole` 工具把子任务交给另一角色并附上下文，例如 Planner 拆完任务后委派 Scout 排复习；每次交接在 AgentStep 中记录 `agent_role`；
- **共享黑板**：角色不直接互相对话，而是通过持久化数据（计划/任务/记忆）协作，避免消息螺旋；
- **角色人格克制**：角色差异主要在 system prompt 的职责、工具白名单与输出格式，不做夸张拟人。

### 5.3 实现形态

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class RoleDef:
    name: str
    system_prompt: str
    tools: tuple[str, ...]      # 白名单
    risk_budget: tuple[str, ...]
    handoff: tuple[str, ...]

ROLES: dict[str, RoleDef] = { ... }
```

## 6. 自主档位与工具权限（差异化）

### 6.1 三档自主程度（用户可随时切换，写入 users.autonomy）

| 档位 | 行为 | 适用 |
|---|---|---|
| **L0 步步确认**（默认） | 所有写动作都生成审批，用户批准才执行 | 刚使用、演示给面试官 |
| **L1 低风险自动** | 只读 + 低风险写入（待办增删、专注记录、复习排期）自动；高风险（改计划、批量改任务）仍需确认 | 日常使用 |
| **L2 高自主** | 除高风险动作（删除、归档、对外消息）外全部自动，事后在时间线可回溯 | 信任后 |

### 6.2 工具风险三级

- `read`：只读，任何档位自动放行；
- `write-low`：单条、可逆（创建待办、记录专注、排复习），L1+ 自动；
- `write-high`：影响计划结构 / 批量 / 不可逆（修改计划、批量改任务、删除），任何档位都需确认。

### 6.3 审批卡支持三种决策

**批准** / **拒绝（可带理由，agent 据此 replan）** / **改参数后批准**（在表单里直接改任务标题、日期、优先级，提交为 edited_payload——比原版只有批准/拒绝更进一步）。

### 8.2 编排循环（Observe → LLM → 工具 → 观察 → …）

```python
# app/agent/orchestrator.py
MAX_STEPS = 12

async def run_agent(ctx, goal_text: str, role: str = "Planner",
                    emit: Emitter | None = None) -> None:
    observe_ctx = await observe(ctx)                       # ① Observe
    messages = [
        {"role": "system", "content": ROLES[role].system_prompt},
        {"role": "user",
         "content": json.dumps({"goal": goal_text, "context": observe_ctx},
                               ensure_ascii=False)},
    ]
    for step in range(MAX_STEPS):
        try:
            resp = await asyncio.wait_for(
                ctx.llm.chat.completions.create(
                    model=ctx.model, temperature=0.3,
                    messages=messages, tools=openai_schemas(role)),
                timeout=60)
        except Exception:
            await fallback_and_finish(ctx, emit)           # 规则兜底
            return

        msg = resp.choices[0].message
        messages.append(msg.model_dump(exclude_none=True))
        await persist_step(ctx, step, role, messages)      # 断点状态写 state

        if not msg.tool_calls:                             # 无工具调用 → 收尾
            await emit("message", {"delta": msg.content})
            await finish_run(ctx, "completed", msg.content)
            return

        for call in msg.tool_calls:
            spec = REGISTRY[call.function.name]
            args = json.loads(call.function.arguments or "{}")
            await emit("tool-call",
                       {"tool": spec.name, "args": args, "riskTier": spec.risk})

            if needs_approval(ctx.user.autonomy, spec.risk):
                await suspend_for_approval(ctx, spec, args, messages, emit)
                return                                     # ③ 挂起，等 resume

            result = await dispatch(ctx, spec, args)       # ④ Execute
            messages.append({"role": "tool",
                             "tool_call_id": call.id,
                             "content": json.dumps(result, ensure_ascii=False)})
            await emit("tool-result", {"tool": spec.name, "ok": True})
```

### 8.3 审批后的断点续跑

```python
async def resume_agent(ctx, run, decision: str, edited=None) -> None:
    state = run.state
    messages = state["messages"]
    pending = state["pending_tool_call"]
    if decision == "reject":
        messages.append({"role": "tool", "tool_call_id": pending["id"],
                         "content": json.dumps(
                             {"success": False, "error": "用户拒绝了该动作，请调整方案"})})
    else:
        spec = REGISTRY[pending["name"]]
        result = await dispatch(ctx, spec, edited or pending["args"])
        messages.append({"role": "tool", "tool_call_id": pending["id"],
                         "content": json.dumps(result, ensure_ascii=False)})
    # 从 state 恢复后继续循环（复用 run_agent 的循环体，步数从 state.step 继续）
    await continue_loop(ctx, run, messages, state["step"] + 1)
```

### 8.4 SM-2 间隔复习（新增工具核心算法）

```python
# app/tools/review_tools.py
def sm2(item: ReviewItem, quality: int) -> tuple[float, int, int]:
    """quality 0-5；返回 (ease, intervalDays, repetitions)"""
    if quality < 3:
        return item.ease, 1, 0
    item.repetitions += 1
    if item.repetitions == 1:   interval = 1
    elif item.repetitions == 2: interval = 6
    else:                       interval = round(item.interval_days * item.ease)
    ease = max(1.3, item.ease + (0.1 - (5 - quality) * (0.08 + (5 - quality) * 0.02)))
    return ease, interval, item.repetitions
```

## 10. 实时流式协议（SSE，差异化）

### 10.1 两段式接入（适配浏览器 EventSource 仅支持 GET）

1. `POST /agent/runs`（body: goal/mode/role）→ 创建 queued run，并立即交给后台 asyncio task 启动；返回 `{ runId }`。该请求不执行第二次 run；
2. `new EventSource('/agent/runs/{runId}/stream', { withCredentials: true })` 订阅过程；SSE 只读取和补发持久化事件，不负责触发执行；
3. 对话同理：`POST /conversations/:id/messages` 落库 → `GET /conversations/:id/stream?after=消息id`。

### 10.2 SSE 事件类型（前端时间线逐块渲染）

```
run-started     { runId, mode, role }
thinking        { role, delta }             # 思考增量（可折叠）
tool-call       { toolCallId, tool, args, riskTier }
tool-result     { toolCallId, ok, summary } # 大结果折叠可展开
approval-needed { approvalId, action, payload }   # 运行挂起
progress        { step, maxSteps }
island-effect   { goalId, effect, tiles }   # 驱动 3D：升地块/种树/点灯
message         { delta }                   # 最终回复增量
run-finished    { status, summary }
error           { code, message }
```

### 10.3 交互保证

- `approval-needed` 后流关闭（挂起）；前端 POST 决策到 `/agent/runs/:id/approval`，后端续跑并重新打开 stream；
- 用户点"停止"→ 取消 asyncio 任务，run 置 cancelled，已执行的低风险动作保留并在时间线列出；
- 断线：EventSource 自动重连，凭 runId 从持久化步骤补齐（前端按 step 号去重）。跨域时服务端必须返回具体的允许来源和 `Access-Control-Allow-Credentials: true`，不得使用 `*`。

## 18. 部署方案

Docker Compose：`frontend`（node 构建 → nginx，反代 /api）· `backend`（**python:3.13-slim**，uvicorn 运行）· `postgres`（pgvector 镜像，数据卷）。

文件存储直接使用**阿里云 OSS**，故容器无需挂载持久化上传目录（仅临时目录用于解析）。

上线：HTTPS + 安全 Cookie；启动执行 Alembic 迁移（含 vector 扩展）+ 可选合成 seed；每日 pg_dump。生产环境密钥通过环境变量 / 密钥管理注入，不打进镜像。APScheduler 仅在单实例启用（多副本时用独立调度进程或外部 cron 加锁，避免重复执行）。
